Una definición útil

Jenkins es un servidor de automatización

Observa eventos, ejecuta un proceso reproducible y comunica el resultado al equipo.

Es open source, extensible mediante plugins y describe el proceso como código en un Jenkinsfile.

Una parte clave

Cada etapa tiene una responsabilidad observable

Si una etapa falla, las siguientes no producen un artefacto engañoso.

→

JUnit conserva el reporte aunque las pruebas fallen.

stage('Test') {
  steps {
    sh './mvnw test -B'
  }
  post {
    always {
      junit 'target/surefire-reports/*.xml'
    }
  }
}

stage('Package') {
  steps {
    sh './mvnw package -DskipTests -B'
  }
}

La señal que ve el equipo

El mismo pipeline produce dos decisiones diferentes

✓

Jenkins CI · success

El cambio puede avanzar

Compila · pruebas pasan · artefacto creado
×

Jenkins CI · failure

El cambio vuelve al autor

GitHub bloquea el merge si el estado es obligatorio

Automatizar también exige límites

Un pipeline confiable protege tanto el código como sus credenciales

01

Token mínimo

Solo el repositorio y permisos necesarios.

02

Secretos fuera de Git

Credentials Binding evita copiarlos al código.

03

Webhook verificable

TLS, secreto y acceso restringido.

04

Agentes separados

En producción, no ejecutar builds en el controlador.

Montar /var/run/docker.sock entrega control amplio sobre el host. Debe ser una decisión explícita.
